      • 第三步：生成增强后的提示词
      • 第四步：按反馈迭代（如需要）
    • 输出质量标准
      • 核心原则

      # 提示词增强

      将模糊的任务描述，通过交互式问答，转化为结构清晰、约束明确、输出格式确定的高质量提示词。

      Announce at start: "我正在使用 prompt-enhancer skill，帮你把任务描述优化成高质量提示词"

      # 执行流程

      # 第一步：理解原始意图

      读取用户提供的原始描述，在脑中完成初步分析：

      • 核心任务是什么（动词 + 对象）
      • 缺少哪些关键要素（角色 / 上下文 / 约束 / 输出格式）
      • 属于哪种任务类型（开发 / 分析调试 / Review / 文档）

      不要在此步骤输出分析结果，直接进入提问。

      # 第二步：逐个补全缺失要素

      参考 prompt-best-practices.md 中的六要素和任务类型模板。

      规则：

      • 一次只问一个问题
      • 用选择题而非开放题（2-4 个选项 + 「其他」）
      • 只问对生成提示词真正必要的信息，已能从原始描述推断的不问
      • 最多问 4 个问题，够用就停

      必问（如果原始描述缺失）：

      1. 上下文 — 技术栈 / 项目类型 / 相关文件是什么？
      2. 约束 — 有没有必须遵守或禁止的规则？
      3. 输出格式 — 期望得到什么形式的结果？

      按需问（根据任务类型）：

      • 开发任务：数据结构 / 接口定义是否需要提供？
      • Review 任务：重点检查哪些维度？
      • 迁移任务：源码路径 / 目标技术栈是否明确？

      # 第三步：生成增强后的提示词

      收集到足够信息后，直接输出增强后的提示词，格式如下：

      ✅ 增强后的提示词

      [完整的高质量提示词，可直接复制使用]

      📋 和原始描述的差异

      • 补充了：[列出新增的关键信息]
      • 明确了：[列出原来模糊现在清晰的部分]

      然后询问：「这个提示词符合你的预期吗？需要调整哪里？」

      # 第四步：按反馈迭代（如需要）

      用户提出修改意见后，直接输出修订版本，不再重新提问。

      # 输出质量标准

      生成的提示词必须满足：

      • 任务明确：有具体动词，知道做什么
      • 上下文落地：包含技术栈、文件路径或数据结构等具体信息
      • 约束可执行：用「禁止/必须」而非「建议/最好」
      • 输出格式确定：Claude 知道该产出什么形式的结果
      • 长度适中：不堆砌背景，关键指令放在前面

      # 核心原则

      • 不替用户决策：问题只收集信息，不暗示「正确答案」
      • 够用就停：信息足够生成好提示词时，立即生成，不继续追问
      • 格式优先选择题：降低用户的回答成本
