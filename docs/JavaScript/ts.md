# TypeScript 学习笔记

1. TypeScript 是什么
   TypeScript 是 JavaScript 加上类型检查。

- JavaScript 主要在运行时发现问题。
- TypeScript 可以在开发时检查类型错误，比如传错参数、访问不存在的属性。
- TypeScript 最终会转换成 JavaScript，由浏览器或 Node.js 执行。
  注意：类型检查不会自动验证接口返回的数据。
  类型声明在运行时会被移除，后端返回的数据是否符合预期，仍然需要运行时校验。

2. 类型声明与类型推断
   类型声明
   主动告诉 TypeScript，一个变量、参数或返回值应该是什么类型。
   常见基础类型：
   类型 含义
   string 字符串
   number 数字
   boolean 布尔值
   null 空值
   undefined 未定义
   bigint 大整数
   symbol 唯一标识

类型推断
没有手动声明类型时，TypeScript 会根据上下文推断类型。

- 变量初始化时，可以根据初始值推断。
- 函数可以根据返回内容推断返回值类型。
- 能清楚推断的地方，一般不需要重复声明。
- 函数参数、接口数据等边界位置，通常需要明确类型。

3. 数组、元组和对象
   数组
   数组类型用于限制数组中元素的类型。

- string[]：字符串数组。
- number[]：数字数组。
- (string | number)[]：元素可以是字符串，也可以是数字。
  注意括号：string | number[] 表示“字符串或者数字数组”，含义不同。
  元组
  元组是各个位置有明确类型的数组。
- 通常用于表达固定结构的数据。
- 每个位置可以使用不同类型。
- 可以包含可选元素和剩余元素。
  例如，一个位置表示姓名，另一个位置表示年龄。
  对象
  对象类型用于描述对象有哪些属性，以及每个属性的类型。
- 必填属性：必须提供。
- 可选属性：可以不提供。
- 只读属性：不能通过当前类型直接修改。
  访问可选属性时，需要考虑它可能是 undefined。

4. any、unknown、never、void
   类型 核心含义 常见用途
   any 基本跳过类型检查 临时兼容旧代码
   unknown 类型暂时未知，使用前需要检查 接收未知数据
   never 不可能出现的值 穷尽检查、永远不返回的函数
   void 不要求有可用的返回值 主要执行操作的函数

any 和 unknown 的区别
any 可以直接使用，unknown 必须先确认类型。

- 对 any 访问属性、调用方法，通常不会受到类型检查限制。
- 对 unknown，需要先进行类型判断或其他收窄操作。
- any 会削弱后续代码的类型检查，因此应尽量减少使用。
  never 和 void 的区别
- void：函数可以正常结束，但调用方不应依赖它的返回值。
- never：函数不会正常返回，比如始终抛出错误或无限循环。

5. 联合类型与交叉类型
   联合类型：|
   表示一个值可以是几种类型中的一种。
   例如：字符串或者数字。

- 使用前通常需要判断具体类型。
- 没有判断时，只能执行所有成员都支持的操作。
  交叉类型：&
  表示一个值必须同时满足多个类型的要求。
  常用于组合对象类型，例如同时拥有用户信息和权限信息。
  注意：交叉类型并不总能成功组合。互相冲突的要求可能产生 never。

6. 字面量类型
   字面量类型用于限制具体值，而不只是限制大类。
   例如，订单状态只允许：

- 待支付
- 已支付
- 已取消
  相比普通字符串，它可以避免拼写错误，也能提供更准确的编辑器提示。
  常见用途：状态、按钮尺寸、主题、接口操作类型。

7. interface 和 type
   两者都可以描述对象结构。
   对比项 interface type
   描述对象 支持 支持
   定义联合类型 不能直接定义 支持
   定义元组、基础类型别名 不适合 支持
   扩展 主要使用 extends 常使用交叉类型
   同名声明合并 支持 不支持

简单记忆：

- interface 常用于描述对象和可扩展的接口。
- type 适合联合类型、元组和各种类型组合。
- 普通对象类型，两者都可以，保持项目风格一致即可。

8. 函数类型
   函数类型主要描述参数和返回值。
   需要关注：

- 参数的类型。
- 参数是否可选。
- 剩余参数的类型。
- 返回值的类型。
  函数重载
  同一个函数，根据不同参数形式，提供不同的返回类型。
  适用于参数与返回值存在明确对应关系的情况。
  如果一个联合类型就能清楚表达，一般不需要使用重载。

9. 泛型
   泛型是在定义时保留类型位置，在使用时确定具体类型。
   它既能复用逻辑，也能保留类型信息。
   例如：一个通用方法接收某种类型的数据，返回的数据仍然保留这个类型。
   泛型和 any 的区别

- any：丢失类型信息。
- 泛型：保留输入、输出或属性之间的类型关系。
  泛型约束
  限制传入的类型必须满足某些条件。
  例如，要求传入的对象必须有某个属性，这样才能安全地访问它。
  泛型也支持默认类型，未指定时使用默认值。

10. 类型收窄
    类型收窄就是通过判断，将宽泛类型缩小为更具体的类型。
    常见方式：

- typeof：判断字符串、数字、布尔值等。
- instanceof：判断是否是某个类的实例。
- in：判断对象是否存在某个属性。
- 判断是否为 null 或 undefined。
- 根据共同的标识属性判断具体成员。
  可辨识联合
  让不同对象类型拥有一个共同的标识属性，但标识值不同。
  例如，请求状态分为：
- 加载中
- 成功，包含数据
- 失败，包含错误信息
  判断状态后，TypeScript 就能确定当前可以访问哪些属性。
  常用于请求状态、消息类型和业务流程状态。

11. 类型断言与非空断言
    类型断言
    开发者告诉 TypeScript：“我认为这个值是某种类型。”

- 不会转换实际数据。
- 不会进行运行时检查。
- 判断错误时，代码仍可能在运行时报错。
  非空断言
  告诉 TypeScript，这个值此处不会是 null 或 undefined。
  同样不会检查实际值。
  只有确实能够保证非空时才使用，否则优先做判断。

12. 常见类型操作符
    操作符 作用
    keyof 获取某个类型的所有属性名，形成联合类型
    typeof 在类型位置获取某个变量或值的类型
    索引访问类型 获取对象中某个属性对应的类型
    extends 用于接口继承、泛型约束和条件类型判断

注意：JavaScript 中的 typeof 判断运行时类型；TypeScript 类型位置中的 typeof 提取静态类型。 13. 常见工具类型
工具类型 作用
Partial<T> 将所有属性变为可选
Required<T> 将所有属性变为必填
Readonly<T> 将所有属性变为只读
Pick<T, K> 选取指定属性
Omit<T, K> 排除指定属性
Record<K, T> 描述一组键及其对应的值类型
Exclude<T, U> 从联合类型中排除指定成员
Extract<T, U> 从联合类型中提取符合要求的成员
NonNullable<T> 排除 null 和 undefined
Parameters<T> 获取函数的参数类型元组
ReturnType<T> 获取函数返回值类型
Awaited<T> 获取异步结果完成后的类型

注意：Partial、Readonly 等通常只作用于第一层属性，不会自动处理所有嵌套层级。 14. TypeScript 如何判断类型兼容
TypeScript 主要根据结构判断类型是否兼容。

- 重点看需要的属性是否存在、属性类型是否兼容。
- 不要求两个类型名称相同。
- 属性更多的对象，通常可以赋给要求较少的对象类型。
  但直接赋值的对象字面量可能触发多余属性检查，帮助发现属性拼错等问题。

15. 前端项目中的常见用途

- 定义接口请求参数和响应数据。
- 定义组件的 Props。
- 限制状态值和操作类型。
- 描述表单、菜单树等业务数据。
- 为通用组件和工具方法设计泛型。
- 定义事件参数与 DOM 元素类型。

16. 常见易错点

- 大量使用 any：类型检查失去作用。
- 把类型断言当成数据转换：实际数据并不会改变。
- 认为接口类型能验证后端数据：类型在运行时已经被移除。
- 忽略可选属性：使用时可能拿到 undefined。
- 滥用非空断言：隐藏了真实的空值风险。
- 认为只读类型会冻结对象：它主要限制编译阶段的修改，不等于运行时冻结。
- 混淆联合与交叉：| 是满足其中一种，& 是同时满足。
- 关闭严格空值检查：更容易漏掉空值问题
