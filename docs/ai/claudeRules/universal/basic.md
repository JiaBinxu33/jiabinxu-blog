# 基础开发规范

## 核心开发原则
- **确认细节** - 需求不够详细时，先询问确认再实现
- **最小化修改** - 遵守最小化修改原则，不删除无关代码或功能
- **严格按需开发** - 只实现明确提到的功能，不添加额外业务逻辑
- **代码风格一致性** - 从已有代码中寻找示例，遵守项目现有编程风格
- **信息准确度** - 回复前必须验证信息准确性，不得基于假设或推测
- **代码质量优先** - 编写正确、符合最佳实践、遵循 DRY 原则的代码
- **功能完整性** - 全面实现所有请求的功能，不留待办事项
- **版本兼容性** - 确保变更与项目指定的语言或框架版本兼容
- **错误处理** - 添加健壮的错误处理和日志上报
- **边界情况处理** - 始终考虑并处理潜在的边界情况
- **功能验证** - 开发结束后检查是否引入错误，确认构建正常
