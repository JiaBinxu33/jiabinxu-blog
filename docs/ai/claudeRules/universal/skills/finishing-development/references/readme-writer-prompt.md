# README Writer Prompt Template

> **For Cursor**: **使用 `generalPurpose` 类型**（不要用 `explore` 类型）, 可以传 `model: "fast"` 以降低成本

Use this template when dispatching README writer subagents. 可以为多个模块并行派遣多个 subagent。

**Purpose:** 为指定模块目录编写业务导向的 README.md 文件。

```
Task tool (general-purpose):
  description: "Write module README for [模块名]"
  prompt: |
    你是一个模块文档编写员。你的任务是为指定的模块目录编写一份简洁的、业务导向的 README.md。

    ## 目标模块

    - 目录路径: [模块目录路径]
    - 所属功能点: [功能点名称]
    - 功能点描述: [从 TECHNICAL_SPEC 或 feature 文档摘取的功能点描述]

    ## 编写步骤

    1. **读取模块代码**: 读取目录下的所有文件，理解模块做了什么
    2. **理解业务上下文**: 结合功能点描述，理解这个模块在业务中的角色
    3. **编写 README**: 按照下方模板格式编写

    ## 编写方式

    **必须使用 `cp` 命令复制模板，然后填空**：

    1. **复制模板**：
       ```bash
       cp ../assets/MODULE_README_template.md [模块目录路径]/README.md
       ```

    2. **读取实际代码**：读取模块目录下的所有文件，理解模块做了什么

    3. **填入占位符**（严格按照模板格式填充）：
       - `[模块名称]` → 填入实际模块名
       - `YYYY-MM-DD` → 填入当前日期
       - `[一两句话描述...]` → 填入实际职责描述
       - `[核心业务逻辑点 1]` → 填入实际逻辑点
       - `./[主文件]` → 填入实际文件路径
       - 等等

    4. **填写设计文档**（特别注意）：
       - 只列出**直接相关**的功能点文档（修改或新增了本模块代码的功能点）
       - 按时间倒序排列（最新的在最上面）
       - 如果超过 5 个功能点，只保留最近的 5 个
       - 每个功能点一行：`- [feature-xxx.md](路径) — 简短功能描述`
       - 不需要列出 TECHNICAL_SPEC.md 链接（模板已提示用户查看功能点文档）

    5. **删除不适用章节**：
       - 如果模块不涉及特殊业务术语，删除"业务术语"章节
       - 如果无设计文档，删除"设计文档"章节

    ## 严格约束

    **必须遵守**:
    - ✅ 绝对复制：**只能使用** `cp` 命令复制模板，不可直接编写
    - ✅ 严格填空：按模板格式填充，不可改变结构
    - ✅ 简洁：每个填空点用最少的字描述清楚
    - ✅ 无大段代码：可使用文件引用（如 `详见 ./hooks/useXxx.ts`）
    - ✅ 基于实际代码：填入的内容必须基于实际读取的代码

    **禁止**:
    - ❌ 直接编写 README（必须先 cp 模板）
    - ❌ 重写模板结构
    - ❌ 添加模板外的章节
    - ❌ 大段代码粘贴（超过 3 行）
    - ❌ 虚构功能或描述
```
