# WMB 代码质量审查 Subagent 模板

> **For Cursor**:  **使用 `generalPurpose` 类型**（不要用 `explore` 类型）, **不传 model 参数**

用于派遣代码质量审查 subagent 的模板。

**目的**: 验证实施是否构建良好（整洁、经过测试、可维护）

**仅在规范审查通过后派遣。**

```
Task tool (general-purpose):
  description: "审查任务 [N] 的代码质量"
  prompt: |
    你正在审查前端功能实施的代码质量。

    ## 实施内容

    **实施者汇报**: [从实施者汇报中获取]
    **任务来源**: 任务 [N] 来自 [技术方案文件]
    **提交范围**: [base_sha] 到 [head_sha]
    **功能描述**: [任务概述]

    ## 审查重点

    ### TypeScript 质量
    - 类型定义是否准确和完整？
    - 是否避免了 any 类型的滥用？
    - 接口设计是否合理？
    - 泛型使用是否恰当？

    ### React 组件质量
    - 组件职责是否单一明确？
    - Props 设计是否合理？
    - 状态管理是否恰当？
    - 生命周期使用是否正确？
    - Hooks 使用是否遵循最佳实践？

    ### 代码组织
    - 文件结构是否清晰？
    - 导入导出是否整洁？
    - 命名是否具有描述性？
    - 函数是否保持适当大小？

    ### 样式和 UI
    - CSS/样式组织是否合理？
    - 是否遵循设计系统？
    - 响应式设计是否考虑？
    - 可访问性是否兼顾？

    ### 性能考虑
    - 是否有不必要的重渲染？
    - 是否正确使用了 memo/useMemo/useCallback？
    - 是否有潜在的内存泄漏？

    ### 错误处理
    - 是否有适当的错误边界？
    - 用户输入验证是否充分？
    - 异步操作错误处理是否完善？

    ### 测试性
    - 组件是否易于测试？
    - 是否添加了必要的 data-testid？
    - 逻辑是否与 UI 适当分离？

    ### 代码风格
    - 是否遵循项目现有的代码风格？
    - ESLint 规则是否都通过？
    - 格式化是否一致？

    ## 审查标准

    **关键问题** (必须修复):
    - 类型安全问题
    - 性能严重问题
    - 安全漏洞
    - 架构违反

    **重要问题** (强烈建议修复):
    - 可维护性问题
    - 可读性问题
    - 最佳实践违反

    **次要问题** (可选修复):
    - 代码风格细节
    - 微小的优化机会

    ## 汇报格式

    **优势**: [列出实施的亮点]

    **问题** (按严重程度分类):
    - **关键**: [必须修复的问题]
    - **重要**: [强烈建议修复的问题]
    - **次要**: [可选修复的问题]

    **评估**:
    - ✅ 批准 (无关键和重要问题)
    - ⚠️ 有条件批准 (仅有次要问题)
    - ❌ 需要修复 (存在关键或重要问题)

    **如果需要修复，请具体说明**:
    - 问题位置 (文件:行号)
    - 问题描述
    - 建议的修复方案
```
